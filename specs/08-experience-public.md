# Spec: Feature 8 — Experience (public)

Status: **APPROVED** (pending final review of the seed data below)

## Objective

Visitors see Léonard's path — jobs, student jobs, internships and education — as a **vertical timeline** (most recent at the top) of cards, each opening a **detail page**. The home page's right-hand column shows the latest 3 entries (on trial; removable).

Editing experiences in the admin is **feature 9**; this feature delivers the data model, the public API, the public pages, and Léonard's real entries taken from his CV.

## Decisions

- Four kinds with a badge: **Job / Student job / Internship / Education** (`Emploi / Job étudiant / Stage / Formation`).
- **Years only** everywhere (`2023 – 2026`, or `2026` when start and end are the same year); overlaps are fine. No end year = ongoing ("Present" / "Aujourd'hui").
- **Most recent first** (left of the carousel): by start year, then end year (ongoing first), then insertion order.
- **Readable detail URLs**: `/fr/experience/<slug>`.
- **No location** field (Léonard may mention places in descriptions). **No organization link.**
- **Technologies** optional (free text for now, linked to Skills later).
- Initial content inserted by a migration from the CV; summaries are short neutral sentences Léonard will rewrite in the editor.
- Translated fields follow the project convention (`jsonb`, French required; English generated by DeepL in the feature 9 editor — for the seed, English is written from the CV).
- **Vertical timeline, years on the left** (changed at Checkpoint B, replacing the horizontal carousel, which is kept for the personal projects section): a column of years in mono, the line with a dot per entry, the card on the right; on narrow screens the years sit above each card, next to the line.

## Data model — table `experiences`

| Column | Type | Note |
|---|---|---|
| `id` | int, PK | also the final tie-breaker for ordering |
| `slug` | varchar(80), unique | `a-z0-9-` only |
| `kind` | varchar, check `job \| student_job \| internship \| education` | badge |
| `title` | jsonb | job title or degree — translated |
| `organization` | varchar(120) | not translated |
| `start_year` | smallint | check 1950–2100 |
| `end_year` | smallint, nullable | null = ongoing; check `end_year >= start_year` |
| `summary` | jsonb | card text (≤ 220 characters) — translated |
| `description` | jsonb | Markdown for the detail page (≤ 5,000 characters) — translated |
| `technologies` | text[] | may be empty |

## API (public)

| Method & path | Response |
|---|---|
| `GET /api/experiences?lang=en\|fr` | `200 [ {slug, kind, title, organization, start_year, end_year, summary, technologies} ]`, most recent first |
| `GET /api/experiences/{slug}?lang=en\|fr` | `200 {…, description}`; `404` unknown slug; `422` bad `lang` |

## Frontend

**`/:lang/experience`** — `PageHeader` (`~/portfolio/parcours`), then the timeline:
- Ordered list, most recent first: years column (mono) · line with a dot · card.
- Card: `Badge` (kind), title, organization, summary, up to 4 technologies; the whole card links to the detail page (years are not repeated inside the card).
- Empty state if the table is empty.

**`/:lang/experience/:slug`** — eyebrow `~/portfolio/parcours/<slug>`, title, badge, organization, years, Markdown description, technologies, link back to the timeline. Unknown slug → 404 page.

**Home** — right-hand column "Recent path" / "Parcours récent": the latest 3 entries as compact cards linking to their detail pages (hidden when empty).

## Testing Strategy

- **Backend:** list order (including the same-year tie) and localization (French fallback); detail by slug; 404/422; constraints (unique slug, slug format, kind values, year range, end ≥ start); migration inserts the 7 entries; round trip.
- **Frontend:** timeline entries in order with years in the left column ("2026", "2023 – 2026", "Present"), badge and link; empty state; detail page content and 404; home column shows the latest 3.
- **Visual:** Playwright screenshots of the timeline, a detail page and the home page (light/dark, 1280/390 px).

## Boundaries

- **Always:** branch `feature/experience-public`; layered backend; shared blocks (`PageHeader`, `Badge`, `TextLink`, `Reveal`, `MarkdownText`); reduced motion respected.
- **Ask first:** any dependency (none planned).
- **Never:** render description HTML other than through `MarkdownText`.

## Success Criteria

1. `/fr/experience` shows the 7 entries as a vertical timeline, most recent at the top, years on the left, readable at 390 px.
2. Each card opens its detail page at a readable URL; unknown URLs show the 404 page.
3. Badges and years are correct in both languages; English falls back to French.
4. The home page shows the latest 3 entries in its right-hand column.
5. All checks pass; screenshots show no overflow at 390 px in both themes.
